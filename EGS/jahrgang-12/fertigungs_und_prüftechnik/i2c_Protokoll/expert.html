Who is allowed to talk? Controller and targetWer darf sprechen? Controller und Target

I²C works on the master/slave principle. In 2021 the terms “master” and “slave” were replaced throughout the specification by “controller” and “target”. You will find both pairs of terms in data sheets and libraries.

I²C arbeitet nach dem Master/Slave-Prinzip. Im Jahr 2021 wurden in der gesamten Spezifikation die Begriffe „Master“ und „Slave“ durch „Controller“ und „Target“ ersetzt. In Datenblättern und Bibliotheken begegnen Ihnen beide Begriffspaare.

Default addresses of display modules are often 0x27 or 0x3F – depending on the port expander chip on the back.

Die Standardadressen von Display-Modulen sind oft 0x27 oder 0x3F – je nach Port-Expander-Chip auf der Rückseite.

Hex conversion: a second wayHex-Umrechnung: ein zweiter Weg

Instead of adding a leading zero, you can also split the 7 bits from the right into a 4-bit and a 3-bit block. For the default address 0x27: 010 = 2 and 0111 = 7.

Statt eine führende Null zu ergänzen, kann man die 7 Bits auch von rechts in einen 4er- und einen 3er-Block teilen. Bei der Standardadresse 0x27: 010 = 2 und 0111 = 7.

The golden rule of data transferDie goldene Regel der Datenübertragung

How do the ICs on the bus know when a bit is valid? The rule is simple: the data line (SDA) is read when the clock line (SCL) changes to HIGH (rising edge) and while SCL stays HIGH.

Wie wissen die ICs am Bus, wann ein Bit gültig ist? Die Regel beim I²C-Bus ist einfach: Die Datenleitung (SDA) wird gelesen, wenn die Taktleitung (SCL) auf HIGH wechselt (steigende Flanke) und solange SCL auf HIGH bleibt.

The R/W bit: write or read?Das R/W-Bit: Schreiben oder Lesen?

The 7-bit address is always followed by the decisive 8th bit of the first byte: the read/write bit. It sets the direction of communication for the following data bytes.

Nach der 7-Bit-Adresse folgt immer das entscheidende 8. Bit im ersten Byte: das Read/Write-Bit. Es legt die Kommunikationsrichtung für die folgenden Datenbytes fest.

R/W = 0

Write: the controller sends data to the target.Der Controller sendet Daten an das Target. Example: you send a text that is to be shown on the LCD.Beispiel: Sie senden einen Text, der auf dem LCD angezeigt werden soll.

R/W = 1

Read: the controller receives data from the target.Der Controller empfängt Daten vom Target. Example: you query a temperature sensor on the display module. While reading, the target keeps sending data until the controller tells it with a NACK: “I have enough data.”Beispiel: Sie fragen einen Temperatursensor am Displaymodul ab. Beim Lesen sendet das Target so lange Daten, bis der Controller ihm mit einem NACK sagt: „Mir reichen die Daten.“

How do you handle several I²C devices?Wie geht man mit mehreren I²C-Geräten vor?

Every device is connected in parallel to the same lines (SDA and SCL). The only important thing is that each device has a unique address (e.g. 0x27 and 0x26). In the code you simply create a separate object with the matching address for each device.

Jedes Gerät wird parallel an die gleichen Leitungen (SDA und SCL) angeschlossen. Wichtig ist nur, dass jedes Gerät eine eindeutige Adresse (z. B. 0x27 und 0x26) besitzt. Im Code legt man dann einfach für jedes Gerät ein eigenes Objekt mit der passenden Adresse an.

What changes if we want to read instead of write?Was ändert sich, wenn wir lesen statt schreiben wollen?

The 8th bit after the address (the R/W bit) is set to 1 (HIGH) by the controller. From now on the controller no longer sends data, it only generates the SCL clock. The addressed target takes control of the SDA line and clocks its data to the controller until the controller ends with a NACK.

Das 8. Bit nach der Adressierung (das R/W-Bit) wird vom Controller auf 1 (HIGH) gesetzt. Ab jetzt sendet der Controller keine Daten mehr, sondern erzeugt nur noch den SCL-Takt. Das adressierte Target übernimmt die Steuerung der SDA-Leitung und taktet seine Daten zum Controller, bis der Controller mit einem NACK abbricht.

Can I²C cables be any length?Dürfen I²C-Kabel beliebig lang sein?

No. I²C stands for “Inter-Integrated Circuit” and was developed for communication on one circuit board. The longer the cable, the higher the line capacitance. The signal edges become rounded (an RC charging curve). Usually the limit is reached after a few dozen centimetres, unless you reduce the clock rate drastically or use special driver ICs.

Nein. I²C bedeutet „Inter-Integrated Circuit“ und wurde für die Kommunikation auf einer Platine entwickelt. Je länger das Kabel, desto höher die Leitungskapazität. Die Flanken „verschleifen“ (RC-Ladekurve). Meist ist nach einigen Dutzend Zentimetern Schluss, außer man senkt die Taktrate stark ab oder nutzt spezielle Treiber-ICs.

Does every display need its own pull-up resistors?Braucht jedes Display eigene Pull-up-Widerstände?

No, the resistors apply to the whole bus. If you connect several modules that all have pull-ups soldered on, they are connected in parallel. The total resistance drops and the current when pulling the line to ground becomes too high. With many modules you often even have to remove the resistors on some boards!

Nein, die Widerstände gelten für den gesamten Bus. Wenn Sie mehrere Module anschließen, die alle fest eingelötete Pull-ups besitzen, schalten sich diese parallel. Der Gesamtwiderstand sinkt und der Strom beim „Auf-Masse-Ziehen“ wird zu groß. Oft muss man bei vielen Modulen die Widerstände auf einigen Boards sogar entfernen!

Practical example: two displays on the same busArduino_Multi_LCD.ino
#include <LiquidCrystal_I2C.h>  // LCD library

// Create two displays with different addresses
LiquidCrystal_I2C lcdSpannung(0x27, 16, 2); // default address for voltage
LiquidCrystal_I2C lcdStrom(0x26, 16, 2);    // changed address for current

int Poti_Spannung = A0;
int Poti_Strom = A1;

void setup() {
  // 1. Initialise display (voltage)
  lcdSpannung.init();
  lcdSpannung.backlight();
  lcdSpannung.setCursor(0, 0);
  lcdSpannung.clear();
  lcdSpannung.print("U: ");
  pinMode(Poti_Spannung, INPUT);
  lcdSpannung.print("Test!");

  // 2. Initialise display (current)
  lcdStrom.init();
  lcdStrom.backlight();
  lcdStrom.setCursor(0, 0);
  lcdStrom.clear();
  lcdStrom.print("I: ");
  pinMode(Poti_Strom, INPUT);
  lcdStrom.print("Test!");

  delay(5000);

  // Clear and prepare both displays
  lcdSpannung.clear();
  lcdSpannung.print("U: ");

  lcdStrom.clear();
  lcdStrom.print("I: ");

  delay(1000);
}

void loop() {
  // Measure voltage and show it on LCD 1
  int valU = 0;
  valU = analogRead(Poti_Spannung);
  float voltage = valU / 20.23;

  lcdSpannung.setCursor(3, 0);
  lcdSpannung.print(voltage);
  lcdSpannung.print(" V");

  // Measure current and show it on LCD 2
  int valI = 0;
  valI = analogRead(Poti_Strom);
  float current = valI / 100.0; // fictitious conversion factor

  lcdStrom.setCursor(3, 0);
  lcdStrom.print(current);
  lcdStrom.print(" A");

  delay(1000);
}
